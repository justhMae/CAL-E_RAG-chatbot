# CAL-E: A RAG-Powered Calamba Assistant for City Information and Services

CAL-E is an AI chatbot that simplifies public access to Calamba City
government information. Instead of navigating multiple layers of a
traditional website, users ask natural-language questions (e.g. "What
are the requirements for a business permit?") and get immediate,
grounded answers — pulled from the city's actual Citizen's Charter data,
not guessed.

```
User Question
   -> Text Preprocessing (typo correction, greeting/meta detection)
   -> Intent Classification (LogisticRegression on TF-IDF word 1-2 grams)
   -> Query embedding via Google Gemini Embedding API (gemini-embedding-001, 768 dims)
   -> NumPy cosine similarity over a pre-built static vector store
      (+ deterministic office-contact attachment + downloadable forms lookup)
   -> Groq-hosted LLM generates the final answer (Gemini fallback)
```

The app is built to run on **Vercel's free Hobby tier**: no PyTorch, no
sentence-transformers, no ChromaDB, no local model weights, and no disk
writes at request time.

## 🌟 Key Features

* **Retrieval-Augmented Generation (RAG):** Documents are chunked, embedded
  with Google's free `gemini-embedding-001` API, and stored as a static,
  pre-built vector store (`data/vector_store.npz` + `data/chunks_meta.json`)
  that is loaded into memory once per cold start. Retrieval is a single
  NumPy matrix dot product (cosine similarity on L2-normalized vectors).
* **Cloud Generation via Groq:** Answers are generated by a Groq-hosted LLM
  (see `GROQ_MODEL` in `backend/config.py`) through the official `groq` SDK,
  with fallback models and a Gemini (`google-genai`) fallback on rate limits.
* **Lightweight Intent Classification:** TF-IDF keyword features (word 1-2
  grams) feed a Logistic Regression classifier (`mode="tfidf"`). The saved
  `backend/intent_model.joblib` loads with only `scikit-learn`, `numpy` and
  `joblib`.
* **Automated Form Lookup:** Directly surfaces relevant downloadable
  government forms (`data/forms/`) to the user based on the matched service.
* **Office Contact Directory:** Service answers that name a handling office
  automatically get that office's real phone/email/location/department head
  attached (via `backend/office_directory.py`), instead of a vague "contact
  them directly."

**Chunking technique:** one chunk per service, not fixed-size sliding
windows. Each entry in `data/documents.json` is a structured record
(office, requirements table, process-flow table, fees) — splitting that
by character count would separate a fee from the step that produced it.
`backend/preprocess.py` flattens each service into one self-contained
chunk (falling back to sliding-window splitting only if a single service
is unusually long, see `STRUCTURED_DOC_MAX_CHARS` in `config.py`).

## 🔑 Environment variables

| Variable | Required | Used for |
|---|---|---|
| `GROQ_API_KEY` / `GROQ_API_KEYS` | yes | Answer generation and follow-up question rewriting (free key: https://console.groq.com). Set `GROQ_API_KEYS` to a comma-separated list (`key1,key2,key3`) to automatically rotate keys when one hits rate limits. |
| `GEMINI_API_KEY` / `GEMINI_API_KEYS` | yes | Query embeddings at runtime, building the index, and the generation fallback (free key: https://aistudio.google.com/apikey). Set `GEMINI_API_KEYS` to a comma-separated list (`key1,key2,key3`) to automatically rotate keys when one hits rate limits or daily quota. |
| `FLASK_SECRET_KEY` | recommended on Vercel | Signs the chat-history session cookie. Without it each serverless instance picks a random key and follow-up questions can lose context. Any long random string works. |

Locally, put them in `backend/.env`:

```
GROQ_API_KEY=your_groq_key
GEMINI_API_KEY=your_gemini_key
```

On Vercel, add them under **Project → Settings → Environment Variables**.

## 🚀 Getting Started

### Run it locally

#### 1. Prerequisites

* **Python 3.10+**
* A **Groq** API key and a **Gemini** API key (see above).

#### 2. Python setup

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt          # runtime deps (what Vercel installs)
pip install -r requirements-dev.txt      # optional: + matplotlib/pyngrok for evaluation & Colab
```

#### 3. Build the static vector store (pre-push step)

```bash
python -m backend.build_index
```

Reads `data/documents.json`, flattens it into chunks with
`backend/preprocess.py`, embeds every chunk with `gemini-embedding-001`
(768 dims, L2-normalized) and writes:

- `data/vector_store.npz` — the `float32` embedding matrix
- `data/chunks_meta.json` — chunk texts and metadata (doc id, title,
  category, office)

Re-run this any time you edit `data/documents.json`, then **commit both
files** — the deployed app only reads them. (The free Gemini tier is
rate-limited; the script backs off and retries automatically, so a full
build can take a few minutes.)

#### 4. Train the intent classifier (pre-push step)

```bash
python -m backend.intent_classifier
```

Trains TF-IDF + LogisticRegression on `data/intent_training_data.csv`,
prints held-out accuracy, then re-fits on all examples and saves
`backend/intent_model.joblib`. Re-run after editing the CSV, then commit
the `.joblib` file.

#### 5. Run the chatbot

```bash
python -m backend.app
```

Open **http://localhost:5000**.

#### 6. Generate evaluation results (for the report/presentation)

```bash
python -m backend.evaluate            # intent metrics only
python -m backend.evaluate --rag      # + sample RAG conversations
```

Produces, in `evaluation/` (requires `requirements-dev.txt`):
- `classification_report.txt` — Accuracy, Precision, Recall, F1-score (macro)
- `confusion_matrix.png`
- `intent_error_analysis.json` — misclassified examples
- `sample_conversations.md` — example Q&A pairs

### Deploy to Vercel (free Hobby tier)

1. Run the two pre-push steps above (`python -m backend.build_index` and
   `python -m backend.intent_classifier`) and commit
   `data/vector_store.npz`, `data/chunks_meta.json` and
   `backend/intent_model.joblib`.
2. Push to GitHub and **Import** the repository in the Vercel dashboard
   (leave the Framework Preset as **Other**; `vercel.json` sets it).
   Or use the CLI: `npm i -g vercel && vercel --prod`.
3. Add `GROQ_API_KEY`, `GEMINI_API_KEY` and `FLASK_SECRET_KEY` as
   Environment Variables, then redeploy.

How the deployment is wired:

- **`api/index.py`** is the Python serverless function; it exports the
  Flask `app` from `backend/app.py`.
- **`vercel.json`** rewrites every route (UI, `/static/*`, `/api/chat`,
  `/api/categories`, …) to that function, except `/api/forms/<file>`,
  which is rewritten to `data/forms/<file>` and served directly by Vercel's
  CDN as an attachment. This keeps large PDFs out of the function bundle
  and avoids Vercel's 4.5 MB function-response limit (some forms are larger).
- `excludeFiles` strips `colab/**`, `evaluation/**`, `venv/**`,
  `chroma_store/**`, the PDFs and secrets from the function bundle, and
  `.vercelignore` keeps `.env`/credentials out of the upload entirely.
- All file paths are resolved from `Path(__file__).resolve()`, data is
  loaded into memory once per cold start, and nothing is written to disk
  during requests (debug logs go to stdout → Vercel runtime logs).

### Run it in Google Colab

The notebooks in `colab/` predate the Vercel refactor (they install the old
`sentence-transformers`/ChromaDB stack). To run the current code in Colab,
upload the project, `pip install -r requirements-dev.txt`, set both API
keys, and run steps 3–5 above.

## 📊 Data status

- **`data/documents.json`** — services scraped from the Calamba City
  website plus office-directory entries for departments (contact info,
  designation, functional statement). See `data/SCHEMA.md` for the field
  reference for both document types.
- **`data/vector_store.npz` / `data/chunks_meta.json`** — generated from
  `documents.json` by `python -m backend.build_index`; do not edit by hand.
- **Downloadable forms** — `data/forms/` holds the PDF assets plus
  `manifest.json`; forms not tied to a specific service are surfaced via
  the "other downloadable forms" flow in `rag_pipeline.py`.
- **Office directory aliases** — abbreviations and Filipino-language
  office names that don't literally overlap with a department's English
  name are mapped in `backend/office_directory.py`.
- **`data/intent_training_data.csv`** — training examples for the intent
  classifier (2,500 unique questions across 18 intents, English and
  Filipino/Taglish paraphrases). Format: a `text,intent` header line, then
  one `question,INTENT` row per line.
- **Intent classifier results** — with the current data, the TF-IDF
  classifier (`C=10`) gets about 0.81 accuracy in stratified 5-fold
  cross-validation (`python -m backend.evaluate`).
