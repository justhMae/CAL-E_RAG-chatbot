# CAL-E: A RAG-Powered Calamba Assistant for City Information and Services

CAL-E is an AI chatbot that simplifies public access to Calamba City
government information. Instead of navigating multiple layers of a
traditional website, users ask natural-language questions (e.g. "What
are the requirements for a business permit?") and get immediate,
grounded answers — pulled from the city's actual Citizen's Charter data,
not guessed.

```
User Question
   -> Text Preprocessing (typo correction, greeting/meta detection)
   -> Intent Classification (LogisticRegression on TF-IDF + MiniLM embeddings)
   -> paraphrase-multilingual-MiniLM-L12-v2 Embedding (sentence-transformers)
   -> ChromaDB similarity search (+ deterministic office-contact attachment)
   -> Groq-hosted LLM generates the final answer
```

## 🌟 Key Features

* **Retrieval-Augmented Generation (RAG):** Documents are chunked, embedded
  using `paraphrase-multilingual-MiniLM-L12-v2`, and stored in ChromaDB for
  fast, relevant retrieval.
* **Cloud Generation via Groq:** Answers are generated by a Groq-hosted LLM
  (see `GROQ_MODEL` in `backend/config.py`) over the Groq API, no local GPU
  or Ollama install required.
* **Hybrid NLP Pipeline:** Combines LLM generation with an intent
  classification layer that joins TF-IDF keyword features (word 1-2 grams)
  and MiniLM sentence embeddings (via scikit-learn `FeatureUnion`) before a
  Logistic Regression classifier. TF-IDF catches exact keywords (form names,
  office abbreviations, fee terms); the embeddings catch paraphrases,
  typos, and Taglish.
* **Automated Form Lookup:** Directly surfaces relevant downloadable
  government forms to the user based on the matched service.
* **Office Contact Directory:** Service answers that name a handling office
  automatically get that office's real phone/email/location/department head
  attached (via `backend/office_directory.py`), instead of a vague "contact
  them directly."

**Chunking technique:** one chunk per service, not fixed-size sliding
windows. Each entry in `data/documents.json` is a structured record
(office, requirements table, process-flow table, fees) — splitting that
by character count would separate a fee from the step that produced it.
`backend/preprocess.py` flattens each service into one self-contained
chunk (falling back to sliding-window splitting only if a single service
is unusually long, see `STRUCTURED_DOC_MAX_CHARS` in `config.py`).

## 🚀 Getting Started

### Run it in Google Colab (recommended if your laptop can't run this locally)

Open one of the notebooks in `colab/` in Google Colab and run the cells
top to bottom. It handles uploading the project, installing dependencies,
building the index, training the classifier, running evaluation, and
launching the web app through an ngrok tunnel so you get a public link
to demo from. 

### Run it locally

#### 1. Prerequisites

* **Python 3.8+**
* **A Groq API key** — get one free at https://console.groq.com, then add
  it to `backend/.env` as `GROQ_API_KEY=your_key_here`.

#### 2. Python setup

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`sentence-transformers` downloads `paraphrase-multilingual-MiniLM-L12-v2`
automatically the first time it runs (cached after that). Generation runs
via the Groq API, so no local model download or GPU is needed for that part.

#### 3. Build the vector index

```bash
python -m backend.build_index
```

Embeds every chunk in `data/documents.json` (including the office
directory entries) and stores it in a local ChromaDB folder
(`chroma_store/`). Re-run this any time you edit `data/documents.json`.

#### 4. Train the intent classifier

```bash
python -m backend.intent_classifier
```

Trains on `data/intent_training_data.csv`, saves to
`backend/intent_model.joblib`, and prints train/test accuracy. The
classifier uses TF-IDF + embedding features together (`mode="union"` in
`build_pipeline()`); pass `mode="embedding"` or `mode="tfidf"` to use
either feature set alone. Re-run this step after editing the CSV or
changing the pipeline, since the saved `.joblib` file holds the trained
model.


#### 5. Run the chatbot

```bash
python -m backend.app
```

Open **http://localhost:5000**.

#### 6. Generate evaluation results (for the report/presentation)

```bash
python -m backend.evaluate            # intent metrics only
python -m backend.evaluate --rag      # + sample RAG conversations
```

Produces, in `evaluation/`:
- `classification_report.txt` — Accuracy, Precision, Recall, F1-score (macro)
- `confusion_matrix.png`
- `intent_error_analysis.json` — misclassified examples
- `sample_conversations.md` — example Q&A pairs

## 📊 Data status

- **`data/documents.json`** — services scraped from the Calamba City
  website plus office-directory entries for departments (contact info,
  designation, functional statement). See `data/SCHEMA.md` for the field
  reference for both document types.
- **Downloadable forms** — `data/forms/` holds the PDF assets plus
  `manifest.json`; forms not tied to a specific service are surfaced via
  the "other downloadable forms" flow in `rag_pipeline.py`.
- **Office directory aliases** — abbreviations and Filipino-language
  office names that don't literally overlap with a department's English
  name are mapped in `backend/office_directory.py`. 
- **`data/intent_training_data.csv`** — training examples for the intent
  classifier (2,500 unique questions across 18 intents, English and
  Filipino/Taglish paraphrases). Format: a `text,intent` header line, then
  one `question,INTENT` row per line.
- **Intent classifier results** — with the current data, stratified 5-fold
  cross-validation gives about 0.81 test accuracy and 0.81 macro-F1
  (`python -m backend.evaluate`).
